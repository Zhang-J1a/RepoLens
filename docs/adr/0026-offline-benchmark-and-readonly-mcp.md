# ADR 0026：暂缓选仓，先完成工程收口与只读接口

- 日期：2026-10-20。
- 状态：已采纳，实施范围由用户本轮指令授权。

## 背景

M4 尚缺足够的独立本地 Python 仓库；用户明确要求先跳过选仓步骤，按已列出的文档、维护性、测试、离线评测准备及 MCP 流程推进，并整理 GitHub 展示。该决定调整执行顺序，不把 M4 或 M5 标为已完成，也不取消检索调优与多语言所需的基线。

## 决策

- README 使用当前同条件检索对照和真实 CI 证据；操作手册与版本历史分别放入使用指南和交接文档。保留尚未添加 LICENSE 的用户决定。
- M9 先以标准库 AST 测量模块和静态依赖；只提取职责独立的 impact Markdown renderer，保留原有导入和输出。兼容 Web/CLI 入口继续保留。
- 模型 benchmark 先提供仅 Mock 的冻结与日志切片。预算在执行前写入，失败/中断预留不返还，恢复不自动重试未知请求；没有真实计费或语义质量结论。
- MCP 采用标准库 stdio 最小实现，固定规范版本 `2025-06-18`，复用现有 ToolContext、validate_action、dispatch_tool、IndexStore.evidence 与 execute_bounded。新增 get_evidence 只允许宿主固定的 head/base snapshot；不增加 shell、写操作、联网或模型能力。
- 本轮不引入 MCP SDK 或其他第三方依赖。支持范围限定为工具发现/调用、初始化和 ping；后续有真实客户端需求时再比较官方 SDK，并单独确认依赖。

## 后果与验收边界

标准库核心可独立打包；MCP 的进程握手及非法路径、版本、证据、预算等有离线验证，但没有第三方客户端互操作或完整协议覆盖承诺。同步 stdio 的取消和并发能力有限，依赖硬超时回收进程。

真实 DeepSeek runner 的 provider、源码外发、请求/token/费用硬上限和独立审阅仍需后续完成。离线 Mock 日志和有效引用不能替代真实回答质量，M4/M5 的缺口继续公开。

# ADR 0012：V3.1 增加有界多轮 chat

## 状态

已接受，适用于 V3.1.0。

## 背景

V2.4 的 `ask` 已经提供自动索引、snapshot 复用和单轮回答，但用户无法在同一个代码版本上继续追问。直接把整个历史无限拼入 prompt 会造成上下文膨胀，也会让模型把上一轮生成文本误当作当前轮证据。

## 决策

1. 增加 `chat --repository <path>` 命令，在一个进程内维护最多 20 轮会话，默认保留最近 8 条 user/assistant 消息。
2. 每一轮都对同一个精确 snapshot 重新检索；历史 user 消息的有限文本参与检索 query，帮助解析省略主语的追问。
3. 历史消息只作为对话上下文发送给 provider，并明确标记为非 repository evidence；当前轮 claim 仍必须引用当前轮打包的 `E1` 等 citation ID。
4. 支持 `:help`、`:quit`、`:exit` 和 `:q`；达到轮数上限或 EOF 时结束。单轮失败只报告错误并保留会话。
5. V3.1 不自动执行目标仓库代码、不修改文件、不调用任意工具、不做追加检索循环。

## 后果

- 用户可以连续询问同一个 snapshot，获得比单轮命令更自然的体验。
- 历史上下文和证据来源保持分离，citation validator 继续提供事实边界。
- 上下文、轮数和历史消息均有界，为下一步 V3.2 的有限追加检索提供可测基础。

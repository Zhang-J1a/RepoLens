# ADR 0016：V4.1 有界多语言代码检索

## 状态

已接受，适用于 V4.1.0。

## 背景

V4.0 的 FTS5 检索可以接受中文输入，但英文源码中的 `main`、`load`、`save` 和 `book` 不会与“入口”“读取”“写入”“书籍”自动重合。结果是纯中文问题容易在 provider 之前 abstain。

## 决策

1. 在 FTS5 查询表达式生成前增加固定中文代码问题词典，覆盖入口、启动、读写、读取、写入、保存、加载、书籍、文件、数据、配置、请求、异常、测试和文档等有限词。
2. 词典只增加英文/代码提示；用户原始 query 和显式 identifier 保留。每个标记最多生成固定数量提示，整体仍遵守 4096 字符和 64 term 上限。
3. `rerank_candidates` 使用同一组扩展提示计算 coverage，保证召回和重排对扩展词保持一致。
4. 扩展层不调用 LLM、不访问网络、不读取仓库内容，也不把扩展结果当作翻译事实；结果仍必须经过现有 evidence span 和 citation validator。
5. 评测新增纯中文 fixture 题，同时继续分别报告原始 lexical 题和扩展后的中文题，避免把有限词典能力称为通用语义检索。

## 后果

- 中文问题可以在常见代码场景中召回对应英文文件和 symbol，例如“主要入口”和 `main`，“书籍数据读写”和 `book_io/load/save`。
- 未覆盖的领域词、同义表达和跨仓库语义仍可能需要用户加入文件名、函数名或英文术语。
- 查询策略 ID 发生变化，检索评测需要记录新的 `FTS_QUERY_POLICY` 和 `RETRIEVAL_POLICY`。
